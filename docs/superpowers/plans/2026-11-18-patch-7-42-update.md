# Patch 7.42 update plan

**Goal:** bring the automation up to date with 7.42. Fix what the patch broke, map the
new items, and automate the new neutral items that are worth it.

**Inputs:** `docs/patch-analysis/7.42/` (notes and impact table). Item behaviour and
descriptions come from Valve's `datafeed/itemdata` and `herodata` endpoints, cached
under `.cache/patch-analysis/7.42/`.

---

## What the patch broke

| # | Problem | Evidence | Severity |
|---|---|---|---|
| B1 | **Meepo MegaMeepo is gone.** `meepo_state.rs` and `meepo.rs` look for `meepo_megameepo`, which no longer exists, so that branch never fires again. | `herodata` for Meepo lists `meepo_earthbind, poof, ransack, petrify, geomancy, divided_we_stand, fling_release` | Dead code; no wrong presses |
| B2 | **Dig now needs Aghanim's Scepter, not Shard.** `should_cast_dig` and the docs gate on `hero.aghanims_shard`. | `meepo_petrify`: `ability_is_granted_by_scepter = true` | **Auto-Dig never fires for a Meepo with only Scepter**, which is now the only way to get Dig. It also needs Shard, which no longer grants it. Dig itself is stronger now (4s, 50% heal, 0.2s cast) |
| B3 | **Mana-cost table is stale.** `mana_costs.rs` still has Khanda, Helm of the Overlord, Javelin and MegaMeepo, lacks every new item, and has the old cost of every changed spell (for example Sleight of Fist 75 → 60). Soul Ring reads this table. | The generator's source, odota/dotaconstants, was last updated 2026-11-13, before the patch | Soul Ring fires on the wrong presses |
| B4 | **Two default neutral items were cycled out.** `item_essence_ring` is still the first entry in `[neutral_items].allowed_items`, and `item_flayers_bota` has a spec. Neither can drop in 7.42. | Valve's item list shows Essence Ring as tier −1 (not a neutral) | Harmless but misleading |
| B5 | **The Item enum in `src/models/items.rs` is stale.** It still lists Hood of Defiance, Poor Man's Shield and Medallion. It is *not* dead (an earlier grep missed the `models::{…, Item}` import): `find_item_slot` takes it, and six variants are used (Blink in Tiny, Meepo, Legion Commander; Blade Mail, Mjölnir, BKB, Orchid, Bloodthorn in Legion Commander). It only maps to a name for `find_item_slot_by_name`. | Grep | Cleanup |

**Checked and fine:** Tiny (no timing constants tied to Avalanche speed), Largo (the
beat worker doesn't depend on Rhapsody's cooldown), Morphling (reads observed
`max_health` deltas, never a stored HP per Strength), dispel and invisibility (no
removed items), and the other scripted heroes (number changes only).

**Re-measure, don't change:** Morphling's simulator constants came from 7.41, when a
point of Strength gave 22 HP; it is now 20. The live code is immune, but
`examples/morphling_shift_control.rs` should be re-run against a fresh probe capture.
The same applies to the unmerged `feat/power-treads` branch: its "220 HP per switch"
is now 200, but it learns per-hero offsets.

## Plan

Each step lands as its own commit. Steps marked 🔬 follow the probe-first contract:
probe → simulator or tests → `src/`.

### Phase 0: groundwork (no gameplay risk)

**P0.1 Mana costs from Valve's feed** (fixes B3)
- Teach `scripts/generate-mana-costs.ps1` to read Valve's datafeed: `herodata`
  for every hero's abilities and `itemdata` for every item. Keep the dotaconstants
  path as `-Source dotaconstants`. Valve's feed carries `mana_costs` arrays in both.
- Regenerate `src/actions/mana_costs.rs` and check the diff: removed items gone, new
  items present, Sleight of Fist at 60.
- Test: the existing Soul Ring tests, plus a spot check that `meepo_megameepo` is
  absent and `item_berserkers_sabatons` is present.

**P0.2 Retire the `Item` enum** (fixes B5)
- `find_item_slot` now takes the item's GSI name (`"item_blink"`), the string form every
  other item lookup in the repo already uses; `find_item_slot_by_name` folded into it.
  `src/models/items.rs` is deleted. A hand-written list goes stale every patch.
- The generated catalog (internal name → display name, neutral tier, behaviour) moves
  to A4, the first thing that needs it.

**P0.3 Neutral defaults** (fixes B4)
- Drop `item_essence_ring` from the `allowed_items` default and from
  `config/config.toml`. Mark `item_essence_ring` and `item_flayers_bota` `Inactive`
  in `ITEM_AUTOMATION_SPECS` rather than deleting them; cycled-out items return.

### Phase 1: Meepo (fixes B1 and B2)

**P1.1**
- Dig: remove the `aghanims_shard` check in `should_cast_dig` (`meepo.rs:44`).
  `ability_is_ready("meepo_petrify")` already proves the ability exists, which now means
  Scepter. Fix the docs.
- MegaMeepo: keep the code, in case it returns. It can't fire, because
  `megameepo_ready` needs the ability in GSI. Default `auto_megameepo_on_danger` to off,
  and label the UI controls as removed in 7.42.
- The new Shard (Divided We Stand pick-up, `meepo_fling_release`) stays manual.
  Carrying the right clone needs a unit target we can't pick from GSI.
- Update `docs/heroes/meepo.md`.

### Phase 2: neutral automation

**A2 Silence dispel learns Flicker, Minotaur Horn and (maybe) Witchbane** 🔬
- Probe written: `examples/neutral_cast_probe.rs` (2026-11-18). It covers A2 and the
  A3 double-tap questions in one session. **Waiting on a capture.** Get silenced, press
  the neutral key, record GSI. Confirm that `silenced` clears, the cooldown edge shows
  the cast, Flicker's blink-in-place rule holds, and whether a Witchbane double tap
  targets the caster.
- **Capture 1** (`logs/neutral_cast/probe_2026-11-18_21-35-29.jsonl`, Huskar, demo
  mode, 223ms median tick):

  | Item | Pressed as | Result |
  |---|---|---|
  | Flicker | single tap, ×2 | Cast edge 158–209ms after the press; blinked 505u and 486u with no damage taken. Not yet cast while silenced or after damage |
  | Minotaur Horn | single tap | Cast edge 73ms after the press: it is no-target (Valve's flags agree), so the spec's double tap is unnecessary but harmless. Not yet cast while silenced |
  | Witchbane | **single tap**, silenced | Cast at the cursor (Quick Cast), and the silence cleared **on the cast tick**. The AoE caught the hero only because the cursor was close. A double tap was not tried |
  | Pollywog Charm | double tap (~130ms apart), then 7 taps | **No cast.** It cast with **Alt+0** (the self-cast modifier) at full HP. Whether the app's 30ms double tap would cast it is unmeasured |
  | Seeds, Riftshadow, Book of the Dead | — | Not captured |

  Reading: item keys are on Quick Cast, where a tap fires at whatever is under the
  cursor. A double tap then has nothing to self-cast onto, and Alt is the reliable
  self-target. This decides how Pollywog, Seeds and Witchbane can be automated.
- **Done 2026-11-18 (user's call: build on capture 1, verify in game).**
  - `DispelItem` gained `Flicker` and `MinotaurHorn`, single press, priority Manta →
    Flicker → Minotaur Horn → Lotus, behind `[danger_detection]
    auto_neutral_on_silence` (default on, toggle on the Survivability page's Dispels
    card).
  - Witchbane is left out: its silence clear came from a cursor-aimed cast.
  - Pollywog went back to `KnownUnsupported` and out of the default list ("leave it
    alone for now"). It needs a modifier self-cast.
  - **Still unmeasured:** Flicker and Minotaur Horn clearing a silence. They are basic
    dispels, which remove silence, but no capture shows it yet. The in-game test is the
    check.
- Then extend `DispelItem` in `dispel.rs` with `Flicker`, `MinotaurHorn` and,
  if the probe passes, `Witchbane`.
  - Order: Manta, Flicker, Minotaur Horn, Lotus, Witchbane. Instant casts first; save
    Minotaur's 40s cooldown for when the cheap options are gone.
  - Same planner, press-settle and cap rules as today.
  - New toggle: `[danger_detection] auto_neutral_on_silence`, shown on the Survivability
    page's Dispels card.
- Flicker also gets a `Danger` / `NoTarget` spec, so it can be used as an escape even
  without silence. **Done with A3**: a no-target press needs no measurement.

**A3 New danger neutrals** 🔬 (Seeds only). **Done 2026-11-18**, except Seeds and
Witchbane, which are specced `KnownUnsupported` until the probe capture. Targeting was
checked against Valve's `itemdata` behaviour flags: Pollywog is unit/ally, Riftshadow,
Flicker and Book of the Dead are no-target, Brick is unit/enemy, and Seeds and
Witchbane are point/AoE.
- Pollywog Charm → `SelfCast`, Supported.
- Riftshadow Prism → `NoTarget`, Supported.
- Book of the Dead → `NoTarget`, Supported, left out of the defaults.
- Brick → `CursorTargeted`, Supported, left out of the defaults.
- Seeds of Serenity → `SelfCast`, only if the probe shows a double tap places it on the
  caster.
- Default `allowed_items` becomes: Ash Legion Shield, Kobold Cup, Pollywog Charm,
  Metamorphic Mandible, Jidi Pollen Bag, Crippling Crossbow, Idol of Scree'auk,
  Minotaur Horn, Flicker, Riftshadow Prism.
- Order matters when several are allowed. One neutral slot means one item at a time,
  so this is only the default list. No priority logic is needed.

**A4 Survivability UI and item catalog**. **Done 2026-11-18.**
- `scripts/generate-neutral-catalog.ps1` writes `src/models/neutral_catalog.rs` from
  Valve's `itemlist`/`itemdata`, sharing the mana generator's cache: name, display name,
  tier, targeting. It covers only the neutral pool (48 items, 12 per tier), since nothing
  else needs a catalog yet.
- The free-text list is now `NeutralItemChecklist`, fed by the `async`
  `get_neutral_items` command. Only supported items can be ticked, and passives are
  collapsed to a count. Entries that left the pool (an old live config's Essence Ring)
  are listed so they can be removed.

### Phase 3: Sabatons of Mordiggian 🔬

**A1 Armlet automation covers `item_berserkers_sabatons`**
- Probe written: `examples/sabatons_toggle_probe.rs` (2026-11-18). **Waiting on a
  capture.** It also re-measures 7.42 Armlet for comparison. In demo mode, record GSI
  while toggling at low HP. Questions:
  1. Does toggling off and back on restore HP the way Armlet does?
  2. How long does the Strength take to ramp in?
  3. Does the drain or the strength loss ever kill?
  4. Does the item JSON show any toggle state? (Power Treads says no.)
- **Capture 1** (`logs/sabatons_toggle/probe_2026-11-18_21-33-50.jsonl`, Huskar, demo
  mode, 223ms median tick, under creep damage throughout):

  | Question | Armlet (7.42) | Sabatons |
  |---|---|---|
  | Max HP per toggle | +500 | +600 once fully ramped (+500 when toggled off again ~0.7s in) |
  | Press → first `max_health` move | 135–287ms | 89–208ms |
  | Press → settled | 730–794ms | 840–1000ms |
  | Toggle state in GSI | **None.** Item JSON identical on and off (`cooldown` 0, `max_cooldown` 0, `can_cast` true); no hero field moves | Same |
  | Off at low HP | — | HP floors at **1–2**, never 0: the Strength loss cannot kill |
  | Off-on double tap from ON, 18–25% HP | — | +62 to +126 HP one second later, but the hero sits at 1–2 HP for a tick in between. One tap at 453 HP **died** 390ms in, at 1 HP under creep hits |
  | Double tap from OFF | — | On-then-off: **−196 HP**. The trick needs the toggle to be ON, and only the `max_health` sign says so |
  | Drain HP/s | not isolated | not isolated: incoming damage throughout |

  Conclusion: Sabatons behaves like Armlet in every way the automation relies on, so
  one implementation fits both. Both share a risk the current logic does not model:
  the trick from the OFF state loses HP. Drain is still unmeasured, but no decision
  depends on it (thresholds are in HP).
- **Done 2026-11-18.** `armlet.rs` now looks up `TOGGLE_DRAIN_ITEMS` (Armlet first,
  then Sabatons) through `find_toggle_drain_slot`. Everything downstream is unchanged:
  the decision is item-agnostic and in HP, so the existing replay tests cover both
  items. No separate `[armlet]` block: the capture showed no reason for a different
  threshold.
- **Follow-up, not built:** track the toggle's inferred on/off state from the
  `max_health` sign after each press, and skip the chord while it is off. This
  applies to Armlet today too.
- Simulator: replay the capture through the existing Armlet replay-model tests in
  `armlet.rs` with Sabatons' measured numbers. Thresholds stay in HP; nothing about
  ramp time goes into the logic.
- Then centralise: one toggle-drain item abstraction that both Armlet and Sabatons use.
  `find_armlet_slot_key` matches either item, preferring Armlet if somehow both are
  held. Sabatons gets its own `[armlet]` override block only if the probe shows a
  different safe threshold.
- Phase Boots automation is unaffected: Sabatons consumes Phase Boots and has no Phase
  active.

## Order and gates

1. P0.1 → P0.3 → P1.1. No probes needed. One evening's work, all covered by unit tests.
2. Probes A2 and A1 in one demo-mode session, recorded by you (they need a live client).
3. A2 → A3 → A4 → A1, each after its probe passes.

Every change also updates `docs/features/survivability.md`, `docs/heroes/meepo.md`,
`docs/reference/configuration.md`, `config/config.toml` and the file index, per
AGENTS.md. Run `cargo test --workspace`, `npx vitest run` and `npx tsc -b --noEmit`
before each commit. Nothing is committed until you have reviewed and tested it.
